## Known limitations

- Hosted GitHub Actions runs were failing before runner steps started across `dev` and PRs; this was classified as CI infrastructure failure, not a code failure.
- Federation was proven with two live P2P nodes and deterministic signed-delta tests, not a three-node Docker deployment.
- Provider quality is a signed observation/aggregate/policy implementation, not a mature public reputation service.
- `upto` is testnet-only and unaudited; do not advertise it as production-ready.
- The custom HTTP seller/client wire path is proven above. Upstream
  `@x402/stellar@2.21.0` still exposes exact only, so stock upstream `upto`
  interoperability remains deferred rather than implied by the custom adapter.
- Pubnet/mainnet was intentionally not executed.
- TLS termination, backup/restore drills, and external caller authentication are deployment/edge responsibilities rather than local Compose features; they are documented as release operations but not claimed as locally proven.
- npm publication of `@veridex/stellar` remains a release step.
- Fresh structured-log sample: `/settle` had 3 settled attempts, 0 failures,
  p50 latency `17317ms`; `/verify` recorded the consumed-authorization replay
  rejection as a deterministic reason.
